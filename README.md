# 课程反馈与访谈的智能分析

综合课程前、课程中和课程后的调查与访谈数据，对课程学习、教学方式、实践方式和考核形式开展系统的文本分析与挖掘，形成有深度、可复核、能够支持改进的分析结果。

## 当前状态

已完成初始数据准备：教师本地数据目录包含47份真实课堂调查的脱敏记录；公开仓库提供24条去关联教学改写片段、题目说明和空白访谈模板。尚未实现分析应用。

## 核心目标

项目覆盖课程全过程，围绕“学生怎样学习、在哪里遇到困难、哪些安排有帮助、应当怎样改进”建立完整的分析链条：从反馈采集与整理，到主题发现、解释比较、证据验证，再到改进建议与后续检查。

- **课程前：**利用教师提供的整体调查数据，了解知识与技术基础、AI使用经验、学习期待、项目兴趣及支持需求，形成课程起点画像。
- **课程中：**由研究小组通过访谈、学习过程记录或小型补充调查等方式收集数据，分析概念理解、学习困难、训练体验、项目协作、教师支持及阶段考核反馈，发现需要及时调整的问题。
- **课程后：**利用教师提供的整体调查数据，分析学习收获、能力迁移、实践成果、未解决困难，以及对教学内容、教学方式和考核形式的整体评价，比较预期与实际体验。
- **贯穿三阶段：**关注不同基础和经历的学生之间的差异、共同主题与反例，解释变化及其可能条件，提出针对学习策略、训练任务、项目实践、内容组织、教学支持与考核设计的具体建议。

分析应结合主题发现、大模型与Agent辅助编码、质性解释和跨阶段比较；每项重要结论都应能回到材料，并说明适用范围和不确定性。详细分析维度、成果要求和访谈安排见[项目任务与访谈安排](docs/PROJECT_BRIEF.md)。

学生可以先围绕一个问题开展组内访谈并完成可复核的分析，再逐步扩展。课前和课后的整体调查数据由教师提供，课中过程数据由研究小组自行收集；能否关联到同一人，以实际提供的数据和授权为准。

## 目录结构

```text
docs/                 需求、数据说明与设计记录
src/                  后续实现代码
tests/                后续测试与评测代码
examples/             空白组内访谈记录模板
data/samples/         24条去关联教学改写片段
data/raw/             受限脱敏反馈及组内访谈，默认不提交
data/processed/       本地处理数据，默认不提交
scripts/              教师本地脱敏脚本
.env.example          本地配置示例
```

## 开始工作

1. 阅读[需求与范围](docs/SCOPE.md)，明确本阶段要完成的功能。
2. 按[数据说明](data/README.md)准备材料和可共享样例。
3. 确定技术方案后补充依赖与启动方式，在`src/`逐步实现，在`tests/`保存对应验证。
4. 为结果保留来源与运行条件，区分教学示例、真实数据和实际模型输出。

目前可直接读取数据、试做分析和开展访谈，尚无应用启动入口或模型调用功能。技术栈、依赖管理与部署方式在后续确定。

## 配置与数据

如后续需要接口配置，可复制`.env.example`为`.env`并填写；当前代码不会读取这些变量。密钥、原始敏感数据和大型模型文件不提交到Git。真实脱敏反馈保存在`data/raw/initial-survey/`，不随GitHub克隆获得，由教师按课程使用范围另行分发。`data/samples/`中的片段为教学概括，不是逐字引文，不能用于统计全班比例；外部代码、模型和数据按其各自许可使用。
